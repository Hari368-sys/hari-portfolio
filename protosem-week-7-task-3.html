IFTTT + Adafruit IO IoT Automation

Trigger an IFTTT applet that drives an Adafruit IO feed and the ESP32 automatically.

← Week 7Task 1Task 2Task 3Task 4Task 5

01Overview

This task adds automation on top of Task 2. A Google Assistant voice command ("Okay Google, activate Bulb On") triggers an IFTTT applet, which sends a value to the bulb-control feed in Adafruit IO. The ESP32 receives it over MQTT and switches the relay and bulb without anyone touching the dashboard.

02Concepts

IFTTT applets

IFTTT (If This Then That) links two services. Here the trigger is a Google Assistant "Activate scene" voice command and the action sends data to Adafruit IO.

Adafruit IO as the action

The "Send data to Adafruit IO" action writes a value to the bulb-control feed, which the ESP32 already listens to.

Automation chain

Trigger, IFTTT, Adafruit IO feed, MQTT, ESP32 and LED run end to end with no manual step.

03System Design

Google Assistant (voice)→IFTTT applet→Adafruit IO feed→MQTT→ESP32→Relay and bulb

04Hardware & Software

Hardware

  • ESP32 development board (ESP32 Dev Module)

Software & platforms

  • IFTTT account (free plan, 2 applets)

  • Adafruit IO account and the bulb-control feed

06Implementation

#include <WiFi.h>
#include "Adafruit_MQTT.h"
#include "Adafruit_MQTT_Client.h"

// =================================================
// Wi-Fi
// =================================================

#define WIFI_SSID "YOUR_WIFI_NAME"
#define WIFI_PASS "YOUR_WIFI_PASSWORD"

// =================================================
// Adafruit IO
// =================================================

#define AIO_SERVER      "io.adafruit.com"
#define AIO_SERVERPORT  1883
#define AIO_USERNAME    "sachinn__s"
#define AIO_KEY         "YOUR_NEW_ADAFRUIT_IO_KEY"

// =================================================
// RELAY
// =================================================

#define RELAY_PIN 23

// Relay logic
#define RELAY_ON  HIGH
#define RELAY_OFF LOW

// =================================================
// MQTT
// =================================================

WiFiClient client;

Adafruit_MQTT_Client mqtt(
  &client,
  AIO_SERVER,
  AIO_SERVERPORT,
  AIO_USERNAME,
  AIO_KEY
);

// =================================================
// BULB FEED
// =================================================

Adafruit_MQTT_Subscribe bulbControl =
  Adafruit_MQTT_Subscribe(
    &mqtt,
    AIO_USERNAME "/feeds/bulb-control"
  );

// =================================================
// CONNECT TO WIFI
// =================================================

void connectWiFi() {

  Serial.print("Connecting to WiFi");

  WiFi.begin(WIFI_SSID, WIFI_PASS);

  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }

  Serial.println();
  Serial.println("WiFi Connected!");
  Serial.print("IP Address: ");
  Serial.println(WiFi.localIP());
}

// =================================================
// CONNECT TO ADAFRUIT IO
// =================================================

void connectMQTT() {

  while (!mqtt.connected()) {

    Serial.print("Connecting to Adafruit IO...");

    int8_t ret = mqtt.connect();

    if (ret == 0) {
      Serial.println("Connected to Adafruit IO!");
    }
    else {
      Serial.print("Failed, error = ");
      Serial.println(mqtt.connectErrorString(ret));

      mqtt.disconnect();
      delay(5000);
    }
  }
}

// =================================================
// PROCESS BULB COMMAND
// =================================================

void processBulbCommand(String command) {

  command.trim();
  command.toLowerCase();

  Serial.print("Received command: ");
  Serial.println(command);

  // -------------------------
  // BULB ON
  // -------------------------

  if (command == "1" ||
      command == "on" ||
      command == "bulb on" ||
      command == "bulbon") {

    digitalWrite(RELAY_PIN, RELAY_ON);

    Serial.println(">>> BULB ON");
  }

  // -------------------------
  // BULB OFF
  // -------------------------

  else if (command == "0" ||
           command == "off" ||
           command == "bulb off" ||
           command == "bulb of" ||
           command == "bulboff" ||
           command == "of") {

    digitalWrite(RELAY_PIN, RELAY_OFF);

    Serial.println(">>> BULB OFF");
  }

  // -------------------------
  // UNKNOWN
  // -------------------------

  else {

    Serial.print("Unknown command: ");
    Serial.println(command);
  }
}

// =================================================
// SETUP
// =================================================

void setup() {

  Serial.begin(115200);

  delay(1000);

  Serial.println();
  Serial.println("================================");
  Serial.println("ESP32 BULB CONTROL");
  Serial.println("================================");

  // Relay setup
  pinMode(RELAY_PIN, OUTPUT);

  // Start with bulb OFF
  digitalWrite(RELAY_PIN, RELAY_OFF);

  // WiFi
  connectWiFi();

  // Subscribe to feed
  mqtt.subscribe(&bulbControl);

  // MQTT
  connectMQTT();

  Serial.println("System ready!");
}

// =================================================
// LOOP
// =================================================

void loop() {

  // Reconnect WiFi if necessary
  if (WiFi.status() != WL_CONNECTED) {
    connectWiFi();
  }

  // Reconnect MQTT if necessary
  if (!mqtt.connected()) {
    connectMQTT();
  }

  // Keep MQTT connection alive
  mqtt.processPackets(1000);

  // Check for new feed value
  Adafruit_MQTT_Subscribe *subscription;

  while ((subscription = mqtt.readSubscription(100)) != NULL) {

    if (subscription == &bulbControl) {

      String command = String((char *)bulbControl.lastread);

      processBulbCommand(command);
    }
  }
}

Key sections of the code:

  • Same sketch as Task 2: subscribes to the bulb-control feed over MQTT
  • processBulbCommand() accepts 1/0 as well as on/off text
  • Relay switched to match the feed value

07Configuration

  1. In IFTTT choose Create, then pick Google Assistant and the "Activate scene" trigger. Connect the service through the Google Home app and name the scene (Bulb On)
  2. Choose the Adafruit service and the "Send data to Adafruit IO" action, then connect and authorize IFTTT in your Adafruit account
  3. Select the bulb-control feed and the data to save, create the action, and continue to finish the applet. Save data 1 for Bulb On. Repeat with the scene "Bulb off" and save data 0 for the off command

08Evidence

09Challenges & Fixes

  • One applet could only ever turn the bulb ON. My first instinct was that a single “Bulb” scene could toggle the light, but an IFTTT Activate-scene trigger only fires an action, it can’t read the bulb’s current state to flip it. I had to create a second, separate applet with its own scene name (Bulb off) and its own action sending 0, so ON and OFF are really two independent automations that happen to write to the same feed.
  • IFTTT couldn’t write to my feed until I authorized it. The first attempt at the action step just sat there, and I realized I hadn’t granted the Adafruit authorization request yet. Approving the “Read and write to your feed data” permission on the Adafruit account page let the action actually save.
  • Making sure the value matched what the sketch expects. Since processBulbCommand() already accepts 1/0 exactly, I just had to type those values into the “Data to save” field rather than leaving IFTTT’s default text in place.

10Reflection

What stood out most is how little the ESP32 side had to change for a completely different kind of trigger. Task 2 proved that publish/subscribe decouples the dashboard from the device, and this task pushed that further: IFTTT is just another publisher on the same feed, alongside the dashboard toggle, and the ESP32 never needs to know which one sent the value. That’s the real payoff of building on Adafruit IO rather than hardcoding a single control path.

The automation does have a seam, though — needing two separate applets for ON and OFF instead of one smart toggle shows that IFTTT’s Activate-scene trigger only knows how to fire a fixed action, not read or branch on current state. Anything more conditional (say, “turn off only if it’s already on”) would need a service on IFTTT’s Pro tier or logic added back on the ESP32 itself.
